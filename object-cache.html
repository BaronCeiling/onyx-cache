Do you need a persistent object cache?

A page cache answers most requests without PHP at all, which is why an object cache is often the second purchase rather than the first. It pays off on sites that stay uncacheable: shops with carts, membership sites, anything with a logged-in audience — and only if a persistent backend is actually connected.

The invalidation trap

Every write must invalidate the keys it affects. Plugins that cache aggressively without group invalidation produce stale prices and phantom stock. Check that changing a product price shows up on the next request before trusting the setup.

How {name} approaches it

Onyx Cache reports object-cache counters and does not ship a drop-in replacement: if your host provides Redis, the counters show whether it is helping; if not, the plugin stays out of the way rather than pretending.

Where it beats a page cache

A cart page cannot be served as shared HTML. Its cost is the queries behind it, and those are exactly what an object cache serves from memory. On a busy shop this is often the difference between 400 ms and 120 ms per uncached request.

Watch the ratio rather than the total: hits divided by requests, over a day. A cache that serves 60% of requests is doing something; 95% means it is covering the site. The same screen shows cache size and the oldest entry, which tells you whether the TTL matches how often the content actually changes.

If the ratio is high and the site still feels slow, the problem is downstream of PHP: images, fonts, or a host network that is saturated. That is the point at which a CDN becomes the right answer, and the counters here are how you know you have reached it.

Who this is for

Anyone who has installed a caching plugin, seen a green score, and still had a slow site. Onyx Cache is aimed at the diagnosis as much as the fix: cache, output size, media and the database are counted separately, so the next thing to change is not a guess. It is not aimed at sites that need an edge network or a support contract.

What it does not do

No CDN. No image CDN. No edge computing, no page builder, no backup, no security firewall. Onyx Cache does not rewrite your theme, does not inject a dashboard banner asking for a review, and does not phone home unless the administrator ticks the box on the dashboard. If a feature needs a remote service to work, it does not belong in a cache plugin.

Frequently asked

Is object caching the same as page caching?

No. Page caching stores finished HTML for anonymous visitors; object caching stores query results for any request, including logged-in ones.

Do I need Redis?

For cross-request benefit, yes — or Memcached. In-process caching alone rarely changes a number you can measure.

Can the two conflict?

They compose, but a page cache serving stale HTML can hide an object-cache invalidation bug. Test with the page cache off first.
