Cleaning the WordPress database without breaking the site

The tables every page reads grow with revisions, expired transients, orphaned post meta and spam. Removing what is provably unused is safe; removing what a plugin still expects is how sites lose settings. Onyx Cache limits itself to the first category and reports the byte count before it deletes anything.

Download plugin.zipWhat Onyx Cache does

Take a copy first

Any cleanup should start with an export. Onyx Cache can write a SQL dump of the affected tables to your uploads directory before deleting, so the state is recoverable without a full-site restore.

Careful: tables belonging to other plugins

Analytics, form entries, e-commerce orders and logs are not junk, even when they are large. Onyx Cache does not touch a table it did not create; if a plugin's table is huge, that plugin owns the retention policy.

Safe: revisions beyond a keep-count

Every save stores a full copy. Keeping three to five per post is plenty for editorial work; the rest is history nobody opens. Deleting them does not touch the published post.

The honest test is a stopwatch, not a score. Load the same page five times with the plugin disabled and five times with it enabled, on the same network, and compare the median. Then check the cache page for a miss count that keeps rising on pages you never visit - that is usually a query string, a cookie, or a form that should have been excluded.

Onyx Cache records what it did per request: whether it served from cache, how many bytes it saved, and how long generation took. Those three values are enough to tell a working setup from one that only looks configured.

Who this is for

Onyx Cache fits a site on one server: a blog, a brochure site, a small shop, a club site with a thousand visits a day. It is the wrong tool for a WordPress network of fifty sites with a shared object cache cluster — that needs infrastructure, not a plugin — and it is unnecessary on a site that already serves static files from a build step.

What it does not do

It will not make a slow host fast, and it will not score well on a lab test that disables caching. It does not touch other plugins' tables, does not replace Redis, and does not promise a Core Web Vitals pass on a theme that ships six JavaScript libraries. Every claim on this page is something the plugin itself performs.

Frequently asked

Will cleanup speed up my site?

It shortens queries on the tables it cleans. Expect a small but real gain, larger on old sites with tens of thousands of revisions.

Can I delete all revisions?

Yes, but keeping a few per post costs almost nothing and preserves editorial history.

Does it touch other plugins' tables?

No. Only rows and tables Onyx Cache created or WordPress marked as disposable.
